## 1. 文档权威性

本文件是 ADS 会议智能体当前唯一的产品需求与验收基线。

需求冲突时按以下顺序处理：

1. 项目负责人在当前任务中的最新明确决定；
2. 本文件；
3. 音频、Prompt、工作流等当前有效专项文档；
4. 技术交接和使用指南；
5. 已归档文档仅用于追溯，不参与当前需求判断。

代码中已经存在的按钮、页面或接口不自动代表需求已经完成。每项能力必须按本文件规定的行为和证据验收。

## 2. 产品定位

ADS 会议智能体是一套面向项目负责人、管理者及普通团队成员的 PC 端会议协作产品。

产品基于 ADS 中已经建立的团队、项目、人员、目标、指标、风险、制度、任务、历史立场和授权边界，完成会前信息聚合、会中决策处理、数字分身代理参会、越权升级、会后任务写回和全过程审计。

核心价值是：

> 用户不需要把同步信息和既定立场重复带入每一场会议。智能体在明确授权内代表用户处理会议，只把真正需要新判断的事项交给本人，并将会议结果转成可跟踪的业务对象。

会议整理与任务闭环、数字分身代理参会同等重要；数字分身是产品的主要差异化能力。

## 3. 核心评判原则

### 3.1 ADS 本体接地与回写

- 会议、议题、发言、决策和行动项必须关联真实 ADS 对象。
- 会议结论必须能够回写为任务、目标进度、风险或决策记录。
- 不允许使用与当前工作区无关的预置数据替代用户业务数据。
- 每个写回结果必须能追溯到会议来源和本人确认记录。

### 3.2 会前聚合与简报

- 根据会议目标自动检索相关项目、目标、指标、风险、任务、制度和历史立场。
- 生成会前简报、建议议程、待确认问题和本场授权建议。
- 对可以异步解决的议题给出会前处理建议，减少不必要的会议占用。

### 3.3 会中决策结构化

- 持续识别共识、争议、风险、决策、负责人、截止日期和事实依据。
- 结构化结果随会议输入更新，不依赖固定文本或固定输出。
- 纪要、决策和行动项必须区分，不能只生成一段摘要。

### 3.4 数字分身代理参会

- 代理身份来自选定 ADS 人员对象。
- 回复必须基于该人员的职责、所属目标、指标、历史立场和授权规则。
- 代理发言必须标注事实依据和授权依据。
- 当前会议中的本人明确指令高于历史立场。

### 3.5 授权内处理与超权升级

- 默认模式为生成回复建议，由本人决定是否发送。
- 每场会议可以单独开启“授权内自动回复”。
- 授权内事项可以自动处理；超权、信息不足、目标冲突或需要新判断的事项必须升级本人。
- 某个事项等待本人处理时，会议和其他授权内事项继续进行。
- 本人可以同意、编辑后发送、拒绝或暂不处理。

### 3.6 一人多会并行

- 至少支持两场会议同时保持进行状态。
- 智能体可以分别维护各场会议的上下文、状态和待办。
- 所有需要本人判断的事项统一进入决策中心，按优先级和截止时间排序。
- 麦克风同一时间只允许被一场会议占用，切换时必须清楚提示占用会议。

### 3.7 会后任务和台账闭环

- 每条行动项独立确认负责人、截止日期、状态和来源。
- 每条行动项可以独立写回、失败和重试，同时提供批量操作。
- 当前写回产品内部 ADS，通过 `WritebackProvider` 保留外部任务系统接入能力。
- 写回后持续显示任务状态，不把“生成纪要”当作流程结束。

### 3.8 全程审计与减负度量

- 保存模型、Prompt 版本、输入来源、输出、授权判断、本人操作和写回结果。
- 原始发言、音频、转写修订、代理发言、决策和任务之间必须可追溯。
- 减负数据必须由真实记录计算，不展示虚构节省比例。
- 至少使用三组真实会议完成改造前后对照。

## 4. 质量等级与完成目标

### 4.1 作品级最低门槛

任何版本至少满足：

- 跑通一个真实高频会议场景；
- 完成会前准备、会中处理和会后写回闭环；
- 完成授权内回应和超权升级；
- 会议、决策和任务建立在 ADS 对象上；
- 提供真实 Prompt、工作流和结构化输出契约；
- 保存不少于三轮真实 AI 输入、输出和使用结果；
- 有可复现操作说明和验收记录；
- 不以固定剧本、预置输出或不可操作页面代替产品能力。

### 4.2 产品级最终目标

本项目最终完成标准为产品级：

- 系统可持续运行，不依赖开发人员现场修改数据；
- 任意会议和任意合法业务输入均可进入真实闭环；
- 支持至少两场会议并行和统一决策汇总；
- 在线 AI、本地语音和本地规则降级均经过真实验证；
- 授权、代理发言、升级和写回全过程可审计；
- 真实减负指标具备基准、口径和来源；
- 核心自动化测试通过率不低于 90%；
- 在干净 Windows 环境完成解压启动和端到端验收；
- UI 达到可长期使用的企业办公产品标准。

项目级能力不属于当前范围，包括多单位长期复用、复杂权限隔离和大规模组织部署。

### 4.3 首个稳定产品版交付线

当前阶段的“产品级”是可以在一台 Windows PC 上长期使用的首个稳定版，不是功能齐全的成熟商业平台。

本版必须达到：

- 首次启动、ADS 工作区、会议创建、会前准备、会中处理、越权升级、会后写回和本地数据管理可以连续操作；
- 所有核心能力在 UI 中可见、可操作、有成功或失败反馈，不以后端接口存在代替产品交付；
- 两场会议并行、麦克风单占用、授权内回复、越权返回原会议和行动项独立写回通过端到端验收；
- FFmpeg、本地 faster-whisper-small 和 sherpa-onnx 匿名说话人分离在断网状态下完成真实音频处理，且不临时下载模型；
- 至少一个 DeepSeek 和一个 OpenAI-compatible 模型使用设置页保存的配置通过真实会议输入验收；
- 1366×768 和 1920×1080 两种 PC 分辨率无主要遮挡、溢出、错位和不可操作控件；
- 前端类型检查、构建、核心自动化测试和干净 Windows 环境启动验收通过。

本版不要求：

- 所有国内模型厂商逐一完成真实调用验收，但必须保留统一扩展接口；
- 多租户、企业级账号和权限体系、局域网多人编辑、移动端、云同步、自动升级和大规模部署；
- 用演示剧本、预存业务数据或前端关键词规则替代真实产品流程。

## 5. 用户与运行模式

### 5.1 目标用户

- 核心用户：项目负责人、部门负责人和需要同时处理多场会议的管理者；
- 兼容用户：普通团队成员和会议组织者；
- 所有角色共用同一产品，不建设独立的管理后台产品。

### 5.2 本地运行模式

- 产品在一台 Windows 电脑上由单个本地用户运行；
- 不要求账号登录、局域网服务器或云端同步；
- 一个本地用户可以创建和切换多个本人身份；
- 一个身份可以参与多个团队业务工作区；
- 创建会议时必须选择代理身份和主要 ADS 工作区；
- 不建设局域网多人同时编辑。

## 6. ADS 工作区与业务对象

### 6.1 工作区定义

ADS 工作区代表一个团队或业务单元，而不是单一会议或单一项目。工作区内部可以包含多个项目及其业务对象。

用户可以创建、编辑、归档和切换多个工作区。新工作区默认为空，不自动注入示例业务内容。

### 6.2 必须支持的对象

- `Team`：团队或业务单元；
- `Project`：项目、产品或专项工作；
- `Person`：人员身份、岗位和职责；
- `Objective`：目标、进度和所属项目；
- `Metric`：目标指标、当前值和目标值；
- `Risk`：风险、影响、责任人和状态；
- `Policy`：制度、标准和约束；
- `Task`：任务、负责人、截止日期和状态；
- `HistoricalStance`：人员对特定主题的历史立场及生效范围；
- `AuthorizationRule`：允许操作、禁止操作和升级条件；
- `Meeting`：会议及其关联上下文；
- `Decision`：会议形成的决策；
- `ActionItem`：待确认和待写回的行动项。

### 6.3 关键关系

```text
团队
  ├─ 人员及职责
  ├─ 项目
  │   ├─ 目标
  │   │   └─ 指标
  │   ├─ 风险
  │   └─ 任务
  ├─ 制度
  ├─ 历史立场
  └─ 授权规则

会议输入
  → ADS 检索
  → 智能体判断
  → 决策
  → 行动项
  → ADS 任务、风险或目标更新
```

## 8. 核心业务流程

### 8.1 首次启动

1. 创建本人身份；
2. 创建空白团队工作区；
3. 配置并测试推荐在线模型；
4. 检查 FFmpeg、本地语音模型和麦克风；
5. 进入空白工作台。

首次启动不预填虚假业务内容。可以提供字段说明和空白模板，不自动创建会议、项目或任务。

### 8.2 创建会议

创建页按三个业务区组织，但不强制分页：

1. 会议信息：名称、开始时间、结束时间、参会人、目标和议程；
2. 会议关联信息：团队工作区、项目、目标、风险、任务和依据；
3. 参会方式与 AI：本人参加或委托智能体、代理身份、模型、本场授权和自动回复开关。

不设置“会议类型”和“预计时长”字段。会议时长由开始时间和结束时间自动计算。

### 8.3 会前准备

- 汇总相关 ADS 对象状态；
- 生成会前简报和建议议程；
- 展示建议立场、允许处理事项和升级条件；
- 允许用户调整本场授权；
- 委托智能体时必须由本人确认后启动代理。

### 8.4 会议现场

- 接收文字、麦克风录音和音频文件；
- 按时间顺序展示会议发言；
- 对每条发言显示 ADS 检索、授权判断和处理结果；
- 持续提取共识、争议、风险、决策和行动项；
- 展示智能体建议回复、已发送回复和依据；
- 等待某项本人决策时继续接收其他会议输入。

### 8.5 决策中心

每个待本人处理事项至少展示：

- 来源会议和议题；
- 对方问题或待决策事项；
- 超权原因；
- 相关目标、指标、风险、制度和历史立场；
- AI 建议、可能影响和截止时间；
- 同意、编辑后发送、拒绝和暂不处理。

本人处理后，原会议时间线必须出现“决定已返回会议”记录，并保存实际回复内容。

### 8.6 会后闭环

- 生成可编辑结构化纪要；
- 展示决策、行动项、负责人、截止日期和依据；
- 每条行动项独立确认和写回；
- 写回后更新 ADS 对象状态；
- 展示来源链、审计记录和本场减负指标；
- 支持导出不包含密钥和原始音频的 Markdown 报告。

## 9. ADS 智能体行为规范

### 9.1 默认行为

- 默认观察、整理、提供建议；
- 有权限并开启自动回复时才代表用户发送；
- 不得编造人员、目标、任务、风险、制度或历史立场；
- 不得把模型推测当作 ADS 事实；
- 不得在信息不完整时自动写回任务。

### 9.2 右侧智能体面板

面板不是通用聊天框，至少包含：

- 当前会议和代理状态；
- 当前模型和连接状态；
- 需要本人处理的事项；
- 正在检索和整理的内容；
- 最新共识、争议、风险和行动项；
- 询问当前会议或 ADS；
- 生成回复、编辑、发送、拒绝和升级；
- 事实依据和授权依据；
- 开始、暂停和继续代理。

所有问答和回复生成必须调用后端统一 AI 工作流，不能由前端关键词规则冒充智能体结果。

### 9.3 本地会议与外部接入

当前版本在本地会议时间线中展示和播放代理回复，并记录发送状态和依据。

架构通过 `MeetingTransportProvider`、`TranscriptProvider`、`AudioTransportProvider` 或同类接口保留外部平台接入能力。当前不接入 Teams、Zoom、腾讯会议等平台，也不展示不可用的平台按钮。

## 10. 一人多会

- 工作台识别会议时间冲突；
- 用户可以选择本人参加其中一场并委托智能体处理另一场；
- 每场会议保存独立输入、模型、授权、代理状态和结果；
- 决策中心跨会议汇总待本人事项；
- 决策处理后准确返回对应会议；
- 至少通过两场并行会议的端到端验收；
- 同一麦克风不能被两场会议同时使用。

## 11. 音频与语音

音频专项行为以当前有效的《ADS 会议智能体本地语音转文字工具需求文档》为补充依据。

### 11.1 当前必须完成

- 分段录音；
- 整场录音；
- MP3、WAV、M4A、WebM 文件上传；
- 单个音频文件不超过 500 MB，时长不超过 4 小时；
- 开始、暂停、继续、结束和取消；
- 录音时长、真实音量和麦克风状态；
- 本地 FFmpeg 预处理；
- 本地 faster-whisper 中文转写；
- 本地 sherpa-onnx 匿名说话人分离，自动输出“发言人 1/2/3”等中性标签；
- 说话人数默认自动判断，并允许在开始处理前手动选择 2～10 人；
- 说话人分离默认开启但允许关闭，失败时保留转写结果并回退为“发言人 1”；
- 单音轨重叠发言采用尽力分配并提示人工核对，不承诺同时完整转写两个人的内容；
- 完整文本、时间片和发言人编辑；
- 语音询问 ADS 智能体；
- 使用 Windows 或浏览器原生 TTS 播放智能体回复，并提供自动播放开关；
- 转写确认后进入统一会议分析流程；
- 音频、原始转写、修订、决策和任务的来源关系。

### 11.2 保存与清理

- 原始音频默认长期保留；
- 用户可以按会议或单条音频删除；
- 用户可以配置 30 天或 90 天自动清理；未开启时不自动删除；
- 删除前展示关联会议、转写和决策影响；
- 音频二进制保存在受控本地目录，不写入 SQLite；
- SQLite 保存元数据、状态、文本、修订和来源关系。

### 11.3 明确不做

- 真实姓名识别、跨会议声纹注册或身份推断；
- 对单音轨重叠发言进行双路音源分离并同时完整转写；
- 连续实时字幕；
- 语音克隆；
- 多端实时音频房间。

## 12. AI 模型与提供商

### 12.1 正式能力

- 在线 AI 是正式主能力；
- DeepSeek 是推荐默认模型；
- 至少真实验证 `deepseek-chat` 或当前可用等价模型；
- 至少真实验证一个通过 Base URL、API Key 和 Model 配置的 OpenAI-compatible 模型；
- 本地规则模式是明确标识的降级能力，不得伪装成在线 AI。

### 12.2 统一提供商接口

所有模型通过统一 `ModelProvider` 工作，统一执行：

- 会前简报；
- ADS 问答；
- 会议回复生成；
- 授权判断；
- 纪要、决策、风险和任务提取；
- 会后总结。

Provider 必须从设置页保存的本地安全配置读取密钥和模型参数，不能只读取开发环境变量。

### 12.3 国内模型扩展

架构为国内主流模型预留适配能力，包括但不限于：

- 阿里云百炼 / 通义千问；
- 火山方舟 / 豆包；
- Moonshot / Kimi；
- 智谱 GLM；
- 腾讯混元；
- 讯飞星火；
- 百度智能云千帆 / 文心系列；
- MiniMax；
- 阶跃星辰 StepFun；
- 百川智能；
- 零一万物 Yi；
- 其他提供 OpenAI-compatible 或独立 API 的模型。

统一接口至少支持 OpenAI-compatible 适配器、厂商专用适配器、Provider 注册表、模型能力声明、连接测试和错误映射。新增厂商不得改写会议业务流程。

预留接口不等于当前完成接入。界面只展示已经配置或具备完整配置入口并可执行连接测试的 Provider，不放置无法调用的厂商按钮。

### 12.4 调用与安全

- API Key 仅保存在本机后端；
- 前端和普通接口不得返回完整密钥；
- 调用记录保存 Provider、模型、耗时、状态、Token 用量和 Prompt 版本；
- 不记录完整密钥；
- 模型输出必须经过结构校验、对象引用校验、授权校验和状态机校验；
- 在线模型失败时显示原因，并允许有限重试、切换模型或进入本地规则模式。

## 13. PC 端 UI 标准

### 13.1 适配范围

- 只建设 PC 端，不考虑移动端适配；
- 完整适配 1366×768 和 1920×1080；
- 常用操作在首屏或一次明确导航内可到达；
- 不因长标题、多人名称、错误信息或状态变化产生重叠和横向溢出。

### 13.2 设计方向

- 定位为高频企业办公软件，不使用营销落地页结构；
- 信息密度适中，优先支持扫描、比较和重复操作；
- 不使用大面积装饰性卡片、渐变球体或无业务价值留白；
- 技术细节放入审计或设置；
- 主操作、风险状态和待本人事项具有明确视觉层级；
- 相同业务对象、状态和操作使用一致组件。

### 13.3 CARP 标准

- 对比：当前会议、超权事项、主要操作和失败状态必须清楚突出；
- 对齐：列表、表单、会议时间和操作按钮遵循稳定轴线；
- 重复：会议、人员、状态、任务和按钮保持一致；
- 亲密性：事实、依据、建议和操作保持在同一业务上下文中。

### 13.4 交互可信度

- 所有可点击控件必须有真实行为；
- 不使用“稍后开放”按钮占据主流程；
- 成功、失败、加载、空状态和未保存变更均有明确反馈；
- 删除、清空和覆盖操作必须确认；
- 键盘焦点、标签和表单错误满足基本可访问性要求。

## 14. 本地数据管理

设置页必须提供：

- 数据库和音频占用概览；
- 导出本地备份；
- 从备份恢复；
- 按会议删除；
- 清理临时和过期音频；
- 恢复为空白工作区；
- 删除前影响提示；
- 操作结果和审计记录。

不建设云同步和复杂版本历史。

## 15. 减负指标

### 15.1 必须记录

- 会议总时长；
- 本人实际参会时间；
- 智能体代理时间；
- 本人决策确认时间；
- 纪要生成时间；
- 人工修改字符数；
- 行动项提取、写回和完成数量；
- 写回耗时；
- 并行会议数量。

### 15.2 基准与展示

- 至少使用三组真实会议材料完成传统处理和系统处理对照；
- 保存采集日期、样本数量、计算口径和数据来源；
- 工作台显示汇总，会议成果页显示本场明细；
- 没有真实基准时显示“待采集”；
- 支持导出包含口径和来源的 Markdown 报告；
- 不根据字符数虚构时间节省比例。

## 16. Windows 交付

最终交付为解压即用的 Windows 包：

- 不要求用户预装 Python、Node.js、Git、FFmpeg 或 Whisper；
- 内置后端运行环境、前端构建产物、FFmpeg 和本地语音模型；
- 在线 AI 仍需要网络和用户配置的 API Key；
- 提供双击启动入口；
- 启动时检查端口、磁盘、模型、FFmpeg、数据库和运行目录权限；
- 启动失败提供可理解原因和日志位置；
- 提供首次启动、模型配置、语音权限、备份恢复和常见故障说明；
- 在一台没有开发环境和模型缓存的干净 Windows 电脑完成验收。

## 19. 验收场景

至少使用以下三类真实会议材料：

1. 项目进度同步：授权内回答进度，形成任务；
2. 方案或技术评审：出现路线变化，触发超权升级；
3. 跨部门协调：涉及多个目标、风险和负责人，形成多条独立行动项。

并行验收至少包含：

```text
会议 A：本人参加并使用麦克风记录
会议 B：委托智能体并开启授权内自动回复
→ 会议 B 产生超权事项
→ 决策中心通知本人
→ 会议 A 继续输入，会议 B 继续处理授权内事项
→ 本人处理决策
→ 回复返回会议 B
→ 两场会议分别形成纪要和行动项
→ 行动项独立写回 ADS
```

## 20. 实施顺序

1. 消除前端类型错误，把已有后端能力完整接入会议现场、智能体面板、ADS 和设置页；
2. 补齐代理身份、本场授权、自动回复、完整 ADS 对象、来源下钻和行动项独立写回 UI；
3. 完成两场并行会议、统一决策中心、越权返回原会议和麦克风单占用验收；
4. 完成音频审计、转写修订、语音问答、失败恢复和真实样本验收；
5. 完成真实模型、减负数据、智能体中心、调用审计和三类真实会议验收；
6. 完成首次启动迁移、数据管理、Windows 发行包、启动自检和干净环境验收。

UI 是每个阶段的首要验收面。后端能力只有在对应 UI 可见、可操作、可恢复时，才视为该阶段交付。

## 21. 状态报告规则

所有进度报告必须区分：

- 已实现：代码具备且有自动化或可复核证据；
- 部分实现：核心逻辑存在，但 UI、异常恢复或端到端证据不完整；
- 未实现：当前产品没有该能力；
- 未验证：代码可能存在，但没有在要求环境中验收。

不得仅以构建成功、接口存在或按钮可见宣称产品已经完成。
