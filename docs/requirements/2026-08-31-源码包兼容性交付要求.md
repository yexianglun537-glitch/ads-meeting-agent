# ADS 会议智能体源码包兼容性交付要求

> 文档状态：本次改动依据，已实施；实际验收范围以任务 6 最终验收记录为准
> 生效日期：2026-08-31
> 适用范围：平台上传用源码 ZIP、Windows CMD 启动、离线基础依赖、Python 3.13 可选语音配置、GitHub 完整版备用入口
> 不替代文档：`ADS会议智能体当前产品需求与验收标准.md`

## 1. 背景与决定

平台单文件上传限制为 20 MB，评委电脑的 Python、Node.js、网络和编译工具版本未知。仅把 PowerShell 7 启动脚本改成 CMD，不能避免 Python 原生依赖、Node.js、npm、Rust/Cargo 和首次联网安装造成的失败。

本次交付采用两层方案：

1. 平台上传“离线轻量源码包”，作为源码审查和基础演示入口；
2. GitHub Releases 提供“完整 Windows x64 一键运行版”，作为没有 Python 或需要完整本地语音能力时的备用入口。

平台源码包优先保证可启动、可完成文字输入主流程和可审查，不在 20 MB 内强行塞入大体积语音模型、FFmpeg、Python 运行时或 Node.js 运行时。

## 2. 交付目标

源码 ZIP 必须同时满足：

- ZIP 文件小于 20 MB；内部验收警戒线为 18 MB；
- 支持 Windows 10/11 x64；
- 支持 CPython 3.11、3.12、3.13、3.14 64 位版本；
- 用户只需双击 `启动项目.bat`，不需要 PowerShell 5.1/7；
- 不要求安装 Node.js、npm、Rust、Cargo、Visual Studio Build Tools；
- Python 已安装时，首次启动不依赖互联网；
- 前后端共用一个 HTTP 服务，默认地址为 `http://127.0.0.1:8000/`；
- 8000 被占用时，从 8001 至 8010 中选择第一个可用端口，并向用户显示实际地址；
- 服务健康检查通过后才打开浏览器和显示成功；
- 启动失败必须给出可执行的中文原因和 GitHub 完整版备用入口；
- ZIP 不包含数据库、`.env`、密钥、日志、用户音频、备份和真实业务数据。

## 3. 运行架构

### 3.1 轻量源码包

轻量源码包包含：

- 完整后端和前端源码；
- 已构建的 `frontend/dist`；
- 基础运行依赖锁文件；
- CPython 3.11–3.14 对应的 Windows x64 离线 wheel；
- CMD 启动入口、使用说明和第三方许可声明。

启动顺序固定为：

1. 检测 Windows x64 和可用 Python；
2. 优先选择 Python 3.13、3.12，再选择 3.14、3.11；
3. 创建或校验 `backend/.venv`；
4. 使用本地 wheel 和 `--no-index` 安装基础依赖；
5. 运行 `pip check`；
6. 设置 `ADS_FRONTEND_DIST` 指向随包提供的前端构建结果；
7. 选择可用端口并启动 FastAPI/Uvicorn；
8. `/api/health` 返回 HTTP 200 后打开浏览器。

产品启动后的语音升级与轻量启动分离：只有 CPython 3.13 x64 显示可执行的一键配置入口，且必须由用户点击后才联网。Python 3.11、3.12、3.14 保留轻量文字模式，并提供手动教程，不宣称完整语音已逐版验证。

### 3.2 GitHub 完整版

完整 Windows x64 版继续包含 Python 运行时、前端构建结果、FFmpeg、本地转写模型和说话人分离模型。文档统一链接到仓库 Releases 页面：

`https://github.com/yexianglun537-glitch/ads-meeting-agent/releases`

不在文档中固定某个版本资产的临时下载地址；每次发布必须同时给出版本号、文件大小和 SHA-256。

## 4. 依赖分层

### 4.1 基础依赖

轻量源码包默认只安装以下能力所需依赖：

- FastAPI/Uvicorn HTTP 服务；
- Pydantic 数据校验；
- `.env` 读取；
- HTTP 客户端；
- multipart 表单解析；
- 当前产品的文字输入、本地规则和演示模式。

基础 Uvicorn 不使用 `[standard]` 扩展，避免引入不必要的原生依赖。`pydantic==2.12.5` 对应 `pydantic-core==2.41.5`，必须同时提供 CPython 3.11–3.14 Windows x64 wheel，禁止现场使用 Cargo 源码编译。

### 4.2 可选完整语音依赖

以下内容不进入 20 MB 源码 ZIP：

- `faster-whisper`、CTranslate2、PyAV；
- `sherpa-onnx`、NumPy 及说话人分离运行时；
- FFmpeg；
- 本地语音转写和说话人分离模型。

轻量源码包必须诚实显示“本地语音组件未随轻量包提供，可继续使用文字输入”。不得把缺少语音组件标为完整可用。CPython 3.13 x64 可由用户点击“一键配置语音”后安装固定依赖并下载固定资源，结束后必须手动重启 ADS。其他 Python 版本仅提供手动教程和健康检查方法；GitHub Windows 版仍是无需配置的完整能力备用入口。

## 5. 体积预算

2026-08-31 临时测算结果：

| 内容 | 当前测算 |
| --- | ---: |
| Python 3.11–3.14 Windows x64 基础 wheel，26 个文件 | 10,537,075 字节（10.05 MB） |
| `frontend/dist`，3 个文件 | 434,348 字节（0.41 MB） |
| 当前源码 ZIP | 约 0.21 MB |
| 目标源码 ZIP | 预计 11–12 MB，必须实测小于 18 MB |

wheel 本身已经压缩，不能假设 ZIP 会显著再次压缩。每次生成交付包后必须以最终 ZIP 实际大小作为验收证据。

## 6. 启动和错误处理要求

CMD 启动器必须区分以下失败原因：

- 未找到 Python；
- 找到的 Python 不是 3.11–3.14；
- Python 不是 64 位；
- 虚拟环境与当前解释器不兼容；
- 本地 wheel 缺失或不匹配；
- `pip check` 失败；
- 8000–8010 全部被占用；
- 后端进程退出或健康检查超时；
- 前端构建结果缺失。

错误提示不得建议用户安装 Rust/Cargo，也不得把升级 pip 作为 `pydantic-core` 版本不匹配的通用解决办法。

## 7. 验收矩阵

| 编号 | 环境 | 必须证明 |
| --- | --- | --- |
| SRC-COMPAT-01 | Windows x64 + Python 3.11，无 Node、断网 | 离线安装、启动、首页和健康接口成功 |
| SRC-COMPAT-02 | Windows x64 + Python 3.12，无 Node、断网 | 同上 |
| SRC-COMPAT-03 | Windows x64 + Python 3.13，无 Node、断网 | 同上 |
| SRC-COMPAT-04 | Windows x64 + Python 3.14，无 Node、断网 | 不触发 Cargo，首页和健康接口成功 |
| SRC-COMPAT-05 | 8000 已被占用 | 自动选择 8001–8010，并打开实际地址 |
| SRC-COMPAT-06 | 中文和带空格的解压路径 | 双击 CMD 可启动 |
| SRC-COMPAT-07 | 无管理员权限 | 在可写解压目录中可启动 |
| SRC-COMPAT-08 | 最终 ZIP 清单 | 小于 18 MB，禁止内容为 0 |
| SRC-COMPAT-09 | 轻量模式 | 文字输入主流程可完成，语音能力状态如实显示 |
| SRC-COMPAT-10 | 无可用 Python | 明确提示 Python 要求和 GitHub Releases 备用入口 |
| SRC-COMPAT-11 | Python 3.13 x64 一键语音配置 | 必须主动点击；固定命令和资源；失败不影响文字；完成后提示重启 |
| SRC-COMPAT-12 | Python 3.11、3.12、3.14 完整语音 | 文档标为手动配置且未逐版验收，不得显示为一键支持 |

未在实际环境执行的矩阵项必须标为 `未验证`，不能用 wheel 下载成功替代完整首次启动证据。

## 8. 本次不做

- 不在源码 ZIP 内嵌 Python 解释器；
- 不在源码 ZIP 内嵌 Node.js 或 `node_modules`；
- 不在源码 ZIP 内嵌语音模型和 FFmpeg；
- 不承诺 macOS、Linux、Windows ARM64；
- 不修改产品业务范围和会议流程；
- 不为了兼容任意环境引入 Docker、系统 Python 安装器或静默联网下载；
- 不承诺 Python 3.11、3.12、3.14 的完整语音依赖已逐版本通过。

## 9. 完成定义

只有在以下条件同时满足时，本次兼容性改造才可标为完成：

1. 轻量源码 ZIP 实际小于 18 MB；
2. ZIP 内包含源码、前端构建结果、离线 wheel、CMD 入口和使用说明；
3. Python 3.11–3.14 的 wheel 解析全部通过；
4. 可获得的实际 Python 环境均完成独立解压首次启动；
5. 未实际执行的环境明确标记为未验证；
6. GitHub Releases 备用入口已写入 README 和使用教程；
7. 最终 ZIP 的 SHA-256、文件数、禁止内容检查和 HTTP 验收结果均已记录。
8. Python 3.13 x64 一键配置接口、界面状态、失败降级和重启提示通过验收；其他版本的手动教程与未验证边界保持一致。
