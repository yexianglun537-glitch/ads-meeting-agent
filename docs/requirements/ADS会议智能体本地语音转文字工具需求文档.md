# ADS 会议智能体本地语音转文字工具需求文档

## 1. 文档信息

- 文档用途：指导 ADS 会议智能体语音输入、音频转写及会议分析衔接功能的设计、开发、测试与产品交付。
- 产品阶段：以当前唯一产品基线定义的作品级门槛和产品级目标为准。
- 运行环境：Windows 本地运行优先。
- 核心技术路线：浏览器录音 + FastAPI + FFmpeg + faster-whisper + sherpa-onnx。
- 文档日期：2026-08-25。

## 2. 背景与问题

ADS 会议智能体当前主要通过会议文字输入完成会前简报、授权判断、代理回复、结构化纪要和任务回写。仅支持粘贴文字会降低实际会议场景的可信度和使用效率。

DeepSeek 的 `deepseek-chat` 和 `deepseek-reasoner` 用于理解和处理文本，不负责音频转写。因此需要内置一套独立的语音转文字模块，把麦克风录音或音频文件转换成可编辑文字，再送入现有 DeepSeek 和 ADS 会议工作流。

## 3. 产品目标

本工具需要做到：

1. 用户可以在会议页面直接录音并获得中文转写结果。
2. 用户可以上传常见音频文件进行转写。
3. 转写文字可以编辑、拆分和修正发言人。
4. 转写结果进入与手动文字输入相同的分析、授权和回写流程。
5. 音频、转写片段、原始发言、决策和任务之间可以追溯。
6. 默认在本地完成语音识别，不依赖 DeepSeek，也不要求产品运行时下载模型。
7. 转写失败、权限被拒绝或设备不可用时，提供明确的恢复方式。
8. 对单音轨会议录音进行本地匿名说话人分离，输出可编辑的中性发言人标签。

## 4. 非目标

本期不强制实现：

- 真实姓名识别、声纹注册、跨会议身份关联或身份推断；
- 对单音轨重叠发言进行双路音源分离并同时完整转写；
- 毫秒级连续实时字幕；
- 语音克隆；
- 智能体使用用户声音发言；
- 电话、Teams、Zoom 等外部音视频流接入；
- 云端语音服务作为唯一转写方式。

## 5. 核心用户场景

### 5.1 分段录音

用户在代理会议室点击“开始录音”，说完一段话后点击“结束并转写”。系统将该段音频转成一条新的会议发言，用户确认或修改后加入会议时间线，并触发智能体分析。

### 5.2 整场会议录音

用户开始整场录音。会议结束后，系统转写完整音频，按时间片生成会议文本。用户完成必要校正后，系统生成结构化纪要、决策和行动项。

### 5.3 上传已有音频

用户上传 MP3、WAV、M4A 或 WebM 文件。系统检查文件后开始本地转写，并显示进度、耗时和结果。

### 5.4 语音询问 ADS 智能体

用户在 ADS 智能体输入区按住或点击录音，转写出问题文字，确认后提交给 DeepSeek。语音只替代文字输入，不改变问答和授权逻辑。

## 6. 功能需求

### 6.1 麦克风录音

- 支持浏览器请求麦克风权限。
- 支持开始、暂停、继续和结束录音。
- 显示录音状态、持续时间和基本音量反馈。
- 录音期间明确提示用户正在采集音频。
- 防止用户重复启动多个录音任务。
- 页面关闭或切换会议前提示仍有未保存录音。

### 6.2 音频上传

- 支持 MP3、WAV、M4A、WebM，条件允许时支持 MP4 中的音轨。
- 显示文件名称、大小、时长和格式。
- 对不支持的格式、空文件和过大文件给出明确提示。
- 单个文件上限为 500 MB，最长 4 小时；超过任一限制时要求用户压缩或拆分。
- 上传后允许用户取消转写。

### 6.3 音频预处理

- 使用 FFmpeg 将输入统一转换为适合 Whisper 的单声道音频。
- 统一采样率，建议为 16 kHz。
- 保留原始音频文件和转换后文件的来源关系。
- 预处理失败时返回可理解的错误原因。

### 6.4 本地转写

- 默认使用 `faster-whisper small`。
- CPU 默认采用 `int8` 计算模式。
- 支持中文识别，并允许自动识别语言或手动指定中文。
- 返回完整文本和带时间戳的分段结果。
- 启用说话人分离时返回词级时间戳，供说话人区间与文字精确对齐。
- 返回转写耗时、音频时长、模型名称和处理状态。
- 模型必须随 Windows 交付包提供，不能依赖首次运行时下载。
- 如果 `small` 在目标电脑上性能不可接受，应支持切换到 `base`。

### 6.5 转写编辑与发言人修正

- “区分不同发言人”默认开启，但用户可以在开始处理前关闭。
- 说话人数默认自动判断，用户也可以在开始处理前手动选择 2～10 人。
- 使用 `sherpa-onnx`、pyannote segmentation 3.0 ONNX 模型和中文 WeSpeaker CN-Celeb ResNet34 模型完成本地匿名分离。
- 自动标签只使用“发言人 1/2/3”等中性名称，每个会议任务重新编号，不跨会议关联身份。
- 按词级时间与说话人区间的最大重叠分配文字，并按说话人变化重新组合片段。
- 单音轨中存在重叠发言时，尽力分配给重叠时间最长的说话人，并在对应片段显示“重叠发言，建议人工核对”。
- 说话人分离模型缺失、加载失败或没有得到有效区间时，转写任务仍进入审核，全部片段回退为“发言人 1”并显示恢复提示。
- 用户可以编辑完整转写文本。
- 用户可以编辑单个时间片内容。
- 用户可以为每段选择或输入发言人。
- 默认使用“参会人”“发言人 1”等中性标签，不得编造具体人员。
- 用户确认后，转写片段才进入正式会议记录。
- 修改前的原始转写应保留在审计数据中。
- 自动处理不得覆盖用户已经手工修改的发言人标签。

### 6.6 与会议流程集成

- 转写文本与手动输入文本使用同一分析接口和状态机。
- 分段录音可以追加为新的 `transcript_turn`。
- 整场录音可以生成完整会议分析。
- 智能体必须根据实际转写内容判断授权内回应和超权升级。
- 转写不负责生成决策；决策、纪要和任务由语言模型及后端规则处理。
- 负责人或截止日期缺失时，继续使用现有“本人补全后才能回写”规则。

### 6.7 来源追溯

每条转写片段至少记录：

- 音频来源 ID；
- 会议 ID；
- 开始和结束时间；
- 原始转写文本；
- 用户修订文本；
- 发言人标签；
- 使用的转写模型；
- 转写时间；
- 后续关联的决策、行动项或任务 ID。

## 7. 用户界面需求

### 7.1 会议页面录音区

至少包含：

- “开始录音”主按钮；
- 当前录音时长；
- 音量或波形反馈；
- 暂停、继续、结束并转写；
- 麦克风设备和权限状态；
- 当前转写进度；
- 转写完成后的编辑确认区。

### 7.2 音频上传区

- 支持点击选择和拖放上传。
- 清楚显示支持格式和大小限制。
- 显示上传、预处理、转写、完成或失败状态。

### 7.3 错误与恢复提示

必须覆盖：

- 麦克风权限被拒绝；
- 未检测到麦克风；
- 浏览器不支持录音；
- 录音文件为空；
- FFmpeg 转换失败；
- Whisper 模型不存在或加载失败；
- 内存不足；
- 音频格式不支持；
- 转写任务中断；
- 磁盘空间不足。

每个错误都应给出下一步操作，例如重新授权、切换设备、改用上传文件或重新启动本地服务。

## 8. 技术架构

```text
浏览器麦克风 / 音频文件
          ↓
MediaRecorder / 文件上传
          ↓
FastAPI Speech API
          ↓
FFmpeg 格式转换与音频检查
          ↓
SpeechToTextProvider
          ↓
FasterWhisperProvider
          ↓
可编辑 Transcript 与 Segments
          ↓
现有会议分析、授权、确认和 ADS 回写流程
```

### 8.1 提供商接口

建议建立统一的 `SpeechToTextProvider`：

- `transcribe(audio_path, language, options)`；
- `health()`；
- `model_info()`；
- `cancel(job_id)`，条件允许时实现。

转写继续使用 `FasterWhisperProvider`；匿名说话人分离作为转写后的本地处理步骤接入，不为单一实现增加额外工厂或不可用入口。

### 8.2 建议后端接口

- `POST /api/speech/jobs`：上传音频并创建转写任务；
- `GET /api/speech/jobs/{job_id}`：查询进度和结果；
- `POST /api/speech/jobs/{job_id}/cancel`：取消任务；
- `POST /api/meetings/{meeting_id}/transcript-segments`：确认并追加转写片段；
- `GET /api/speech/health`：检查 FFmpeg、模型和运行设备状态。

上传接口同时接收：

- `diarization_enabled`：布尔值，默认 `true`；
- `speaker_count`：可空整数，空值表示自动判断，非空时只能为 2～10。

### 8.3 建议数据对象

- `AudioSource`：原始音频及元数据；
- `TranscriptionJob`：转写任务和状态；
- `TranscriptSegment`：时间片、文本和发言人；
- `TranscriptRevision`：用户修改记录；
- `SpeechModelInfo`：模型名称、版本、设备和计算模式。

## 9. 任务状态

转写任务建议采用：

```text
uploaded → preprocessing → transcribing → diarizing → awaiting_review → confirmed
      └→ failed
      └→ cancelled
```

- 只有 `confirmed` 的文本可以进入正式会议分析。
- 失败任务允许重新尝试。
- 用户修改转写后应保存修订记录。
- `diarizing` 阶段可以取消；分离失败不把整个任务改为 `failed`，而是带警告进入 `awaiting_review`。

## 10. 数据存储与清理

- 音频和转写默认保存在本地项目数据目录。
- SQLite 保存元数据、状态、文本和来源关系。
- 音频文件使用独立目录保存，不把二进制写入 SQLite。
- 提供删除单个音频和清空临时音频的入口，不提供填入或重新载入示例数据的产品入口。
- 删除音频前提示其关联的会议、转写和决策记录。
- 验收音频与用户录音分目录保存。
- 音频、转写或日志不得包含 API Key。
- 原始录音默认长期保留；用户可以选择 30 天或 90 天自动清理，未开启时不自动删除。

## 11. 隐私与安全

- 开始录音前必须由用户主动操作。
- 页面持续显示录音状态，不能后台静默录音。
- 音频默认只在本机处理和保存。
- 如果未来增加在线 ASR，上传前必须明确提示用户。
- 文件名和路径需要防止目录穿越。
- 限制文件大小、格式和并发任务数。
- 导出的会议纪要默认不包含原始音频文件。

## 12. 性能与稳定性要求

第一阶段建议验收目标：

- 1 分钟普通话会议音频可成功转写。
- 转写结果能够正常编辑并进入会议流程。
- 普通 CPU 环境下，1 分钟纯转写目标在 60 秒内完成；启用匿名说话人分离后的目标为 90 秒内完成，最终阈值根据目标电脑实测调整。
- 后端转写时前端保持可操作并显示进度。
- 单个任务失败不影响会议、任务和其他音频数据。
- 重启本地服务后可以查看已完成任务和失败原因。
- 重复提交同一确认操作不会生成重复会议发言。

## 13. 打包与运行要求

- 最终交付 Windows ZIP。
- ZIP 内包含 FFmpeg、语音模型及必要运行依赖。
- ZIP 内包含 sherpa-onnx Windows CPU 运行库、说话人分段模型、中文声音特征模型和对应第三方许可证，不依赖首次运行下载。
- 解压后通过现有一键启动入口运行。
- 不要求用户手动安装 Whisper 或下载模型。
- 启动时检查模型、FFmpeg、磁盘空间和运行环境。
- 模型路径应支持相对路径，避免依赖开发电脑绝对路径。
- 文档说明包体大小、首次模型加载时间和推荐硬件。

## 14. 测试要求

至少验证：

1. 麦克风授权、拒绝和重新授权。
2. 分段录音、暂停、继续和结束。
3. MP3、WAV、M4A、WebM 上传。
4. 中文短音频和较长会议音频。
5. 空音频、损坏音频和不支持格式。
6. 转写文本编辑和发言人修改。
7. 转写片段追加到会议。
8. 转写内容触发授权内回应。
9. 转写内容触发超权升级。
10. 转写生成行动项并完成 ADS 回写。
11. 模型文件缺失和 FFmpeg 缺失。
12. 服务重启后的任务恢复。
13. 1366×768 和 1920×1080 下的页面布局。
14. 匿名说话人分离开关默认开启且可以关闭。
15. 自动人数、手动指定 2～10 人和至少 2 人中文混合音轨。
16. 安静环境、背景噪声、轮流发言和重叠发言；重叠片段必须提示人工核对。
17. 分离模型缺失、加载失败和无有效说话人区间时的转写回退。
18. 用户手工修改发言人后不被后台自动覆盖。

## 15. 验收标准

- [ ] 可以直接使用麦克风录制一段中文会议语音。
- [ ] 可以结束录音并获得本地转写结果。
- [ ] 可以上传常见音频文件并转写。
- [ ] 转写文字可以编辑和修正发言人。
- [ ] 默认开启本地匿名说话人分离，并输出“发言人 1/2/3”等中性标签。
- [ ] 可以关闭说话人分离，也可以选择自动人数或手动指定 2～10 人。
- [ ] 重叠发言片段具有人工核对提示，分离失败不丢失转写文字。
- [ ] 原始音频、转写和会议对象之间可以追溯。
- [ ] 转写文本能进入现有分析、授权、确认和 ADS 回写流程。
- [ ] DeepSeek 不参与音频识别，只处理转写后的文字。
- [ ] 转写失败时有明确提示和恢复操作。
- [ ] Windows 交付包内置模型，首次运行无需下载。
- [ ] 普通 Windows CPU 可以完成演示场景转写。
- [ ] 不把匿名分离宣传为真实姓名识别，不实现跨会议声纹关联和实时字幕。

## 16. 实施顺序

1. 建立 `SpeechToTextProvider` 接口和本地性能验证脚本。
2. 实测 `faster-whisper base` 与 `small` 的中文准确率、速度和体积。
3. 实现 FFmpeg 预处理和单文件转写接口。
4. 增加音频、任务和转写片段持久化。
5. 接入音频上传和结果编辑。
6. 接入浏览器麦克风录音。
7. 将分段转写追加到会议分析流程。
8. 增加语音提问入口。
9. 完善错误恢复、数据清理和自动化测试。
10. 打包 Windows ZIP，并在干净的普通 Windows 电脑上完成端到端验证。
11. 接入 sherpa-onnx 匿名说话人分离、词级对齐、失败回退、离线模型与发行自检。

## 17. 工作量判断

- 最小上传转写能力：约 1～2 个开发日。
- 录音、进度、校正、持久化和会议集成：约 3～5 个开发日。
- Windows 打包和多设备验证：约 1～2 个开发日。

实际时间取决于目标电脑 CPU 性能、音频格式兼容性和 Whisper 模型包体。
